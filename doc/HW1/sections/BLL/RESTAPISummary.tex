\subsection{REST API Summary}

All REST resources are identified through the prefix \texttt{/rest}, which is omitted in the table below. No servlet filter is mapped to \texttt{/rest/*}; REST authentication and authorization are enforced inside \texttt{RestDispatcherServlet}, which reads the \texttt{auth\_token} HttpOnly cookie, verifies the JWT, sets the \texttt{user\_id} and \texttt{user\_role} request attributes, and applies per-route access rules.

\begin{itemize}
\item Dispatcher Access Guard (DAG): effective REST access-control layer inside \texttt{RestDispatcherServlet}, applied to all \texttt{/rest/*} routes. \texttt{DAG-P} = \texttt{PUBLIC}, \texttt{DAG-A} = \texttt{AUTHENTICATED}, \texttt{DAG-SA} = \texttt{STAFF\_OR\_ADMIN}, \texttt{DAG-ADM} = \texttt{ADMIN\_ONLY}. Missing, invalid, or expired JWTs are treated as unauthenticated and protected routes return \texttt{401} with \texttt{E4A2}; insufficient roles return \texttt{403} with \texttt{E4A4}.
\item DashboardFilter (DF): protects \texttt{/dashboard/*} by validating the \texttt{auth\_token} HttpOnly cookie. Redirects to \texttt{/login} if the token is missing or invalid; otherwise sets the \texttt{user\_id} request attribute. This filter does not apply to \texttt{/rest/*}.
\item AuthFlowFilter (AFF): protects \texttt{/login} and \texttt{/register} by redirecting already-authenticated users to \texttt{/dashboard}. This filter does not apply to \texttt{/rest/*}.
\end{itemize}
